# Agent Pets 0.12: Cursor, Grok Build i ZCode

Status: projekt zatwierdzony w rozmowie z 2026-09-29, do przeczytania przez użytkownika. Rozwija wydanie 0.12 z programu `2026-09-27-agent-pets-more-agents-design.md` (dalej „spec 0.10”) i dokłada ZCode, o który użytkownik poprosił. Wyniki rozpoznania (dokumentacja Cursora i Grok Build, kod ZCode) są w §3; to, czego dokumentacja nie rozstrzyga, zamykamy na żywo (§8).

## 1. Cel

1. **Cursor** jako agent z własnym zwierzakiem: agent w edytorze Cursor i `cursor-agent` w terminalu.
2. **Grok Build** (CLI xAI) jako agent z własnym zwierzakiem.
3. **ZCode** (Zhipu AI / Z.ai, aplikacja i CLI) jako agent z własnym zwierzakiem.
4. **Obcy wywołujący w `hook.exe`:** Cursor, Grok i ZCode uruchamiają też hooki Claude Code z `~/.claude/settings.json`, a Grok także pliki hooków Cursora. `hook.exe` rozpoznaje, kto go naprawdę wywołał, i odrzuca cudze wywołania, żeby nie powstawały duchy Claude'a (2.2).
5. **README:** jasno, na czym się skupiamy (7).

Priorytet projektu (decyzja użytkownika): najważniejsze jest, żeby wszystko działało w **Claude Code, Codex i opencode**. Cursor, Grok i ZCode są dodatkiem: części, których nie sprawdzimy na żywo, wychodzą jako eksperymentalne i tak są opisane (7, 8).

Poza zakresem:
- limity i statystyki Cursora, Groka i ZCode (ich hooki nie niosą tokenów, a pytanie ich serwerów wymagałoby tokenu użytkownika, 9);
- dalsze poprawki Antigravity (decyzja użytkownika: zostaje podstawowa obsługa z 0.11, bez rozwoju);
- stan „czeka na Ciebie” w Cursorze (hooki nie mają zdarzenia o prośbie o zgodę);
- podagenci Groka (dokumentacja nie mówi, czy zdarzenie niesie id rodzica; wracamy do tego po nagraniu, jeśli niesie);
- agenci w chmurze Cursora (ich hooki nie działają na tym komputerze);
- odtwarzanie sesji po restarcie widżetu (jak w 0.11: wracają przy pierwszym zdarzeniu);
- kolejni agenci z kolejki spec 0.10 §1 (Kilo, Qwen, Goose, Junie, Kiro, Cline).

## 2. Wspólny szkielet dla hooków

Rozszerza spec 0.11 §2.

### 2.1 Wywołanie

- `hook.exe --agent <cursor|grok|zcode> --event <nazwa>`, tak samo jak Copilot i Antigravity: nazwa zdarzenia z argumentu, koperta `AgentEnvelope` na `/v1/events/<agent>`, limit 300 ms, kod 0, ciche błędy.
- **Program-gospodarz** tylko przy zdarzeniach początku tury (`host_event`):
  - Cursor: `sessionStart`, `beforeSubmitPrompt`;
  - Grok i ZCode: `SessionStart`, `UserPromptSubmit`.
- **Id sesji Groka:** gdy JSON nie ma `sessionId`, a zmienna `GROK_SESSION_ID` jest ustawiona, `hook.exe` wpisuje ją do `payload.sessionId`. Adapter widzi wtedy tylko JSON, jak u innych agentów.
- **Wyjście:**
  - Cursor: `{"continue":true}` dla `beforeSubmitPrompt`, `{}` dla pozostałych. Nigdy `permission`, `followup_message` ani `user_message`: nie zmieniamy zachowania agenta;
  - Grok i ZCode: nic (kod 0 bez wyjścia = hook bez zdania).
- **Stała ścieżka:** wszystkie pliki wskazują na `~/.agent-pets/hook.exe`. `place_hook` działa, gdy włączona jest którakolwiek integracja przez hooki (furtka, Copilot, Antigravity, Cursor, Grok, ZCode).

### 2.2 Obcy wywołujący

Czysta funkcja w rdzeniu: `adapters::caller(payload, env) -> Option<Caller>`, `Caller = Cursor | Grok | Zcode`. `env` to funkcja odczytu zmiennych, żeby dało się ją testować.

| Warunek (pierwszy pasujący) | Wywołujący |
|---|---|
| ustawiona zmienna `GROK_HOOK_EVENT` | Grok |
| JSON ma pole `cursor_version` | Cursor |
| ustawiona zmienna `ZCODE_SESSION_ID` i JSON ma pole `hookEventName` | ZCode |
| nic z powyższych | brak (wywołanie „własne”) |

- **Tryb Claude** (`hook.exe` bez `--agent`, z `~/.claude/settings.json`): gdy `caller` coś zwraca, `hook.exe` niczego nie wysyła.
- **Tryb `--agent X`:** wysyła tylko wtedy, gdy `caller` zwraca nic albo `X`. Dzięki temu Grok czytający plik Cursora nie tworzy zwierzaka Cursora.
- **Dlaczego Grok jest pierwszy:** Grok uruchamia pliki hooków Cursora i może im podawać JSON w formacie Cursora; zmienną `GROK_HOOK_EVENT` ustawia tylko Grok.
- **Dlaczego ZCode potrzebuje obu warunków:** ZCode może ustawiać `ZCODE_SESSION_ID` w swoim terminalu. Claude Code uruchomiony z tego terminalu dziedziczy zmienną, ale wysyła `hook_event_name`, a nie `hookEventName`, więc nie zostanie odrzucony.
- **Co zyskuje użytkownik:** bez włączonej integracji Cursora, Groka czy ZCode nie widzi żadnego zwierzaka tych agentów (zgoda przed zapisem), a nie fałszywego zwierzaka Claude'a.

## 3. Agenci

### 3.1 Cursor: instalacja

- **Plik:** wspólny plik hooków użytkownika Cursora. Dokumentacja podaje dla Windows `%APPDATA%\Cursor\hooks.json`, inne źródła `~/.cursor/hooks.json`. Ścieżkę rozstrzygamy na żywo (8). Do tego czasu kod ma jedną funkcję `cursor_hooks_path(home)` i test dla wybranej ścieżki.
- **Schemat:** `{"version":1,"hooks":{"<zdarzenie>":[{"command":"\"<hook.exe>\" --agent cursor --event <zdarzenie>","timeout":5}]}}`.
- **Zdarzenia:** `sessionStart`, `sessionEnd`, `beforeSubmitPrompt`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `subagentStart`, `subagentStop`, `preCompact`, `stop`.
- **Włączenie:** dopisanie do cudzej zawartości, bo to plik wspólny:
  - przed pierwszą zmianą kopia `hooks.json.agent-pets-backup`;
  - nasze wpisy rozpoznajemy po komendzie z naszą ścieżką i `--agent cursor`; ponowne włączenie ich nie dubluje;
  - zły JSON → odmowa bez zmian;
  - zapis atomowy.
- **Wyłączenie:** usuwa tylko nasze wpisy i puste tablice zdarzeń. Plik, który sami utworzyliśmy i który został pusty, usuwamy.
- **Wykrycie:** jest katalog `~/.cursor` albo `%APPDATA%\Cursor`. Bez niego włączenie odmawia.

### 3.2 Cursor: tłumaczenie

Id sesji: `conversation_id`, a gdy go brak, `session_id`; musi przejść `safe_id`, inaczej zdarzenie jest pomijane. Model: pole `model` przy dowolnym zdarzeniu → `Meta`.

| Zdarzenie | Stan sklepu |
|---|---|
| `sessionStart` | SessionStart |
| `beforeSubmitPrompt` | Prompt |
| `preToolUse` | ToolStart (rodzaj narzędzia i tekst akcji, niżej) |
| `postToolUse` | ToolEnd |
| `postToolUseFailure`, `is_interrupt: true` | TurnEnd (gotowe) |
| `postToolUseFailure`, pozostałe | ToolEnd |
| `stop`, `status` `completed` albo `aborted` | TurnEnd |
| `stop`, `status: error` | Error |
| `preCompact` | Compact |
| `sessionEnd` | SessionEnd |
| `subagentStart` | mini zwierzak (`SubKind::Cursor`): id `subagent_id`, rodzic `parent_conversation_id`, opis `subagent_type` |
| `subagentStop` | koniec mini zwierzaka |

- **Narzędzia:** mapa nazw Cursora na rodzaje Claude'a (`Shell` → Bash, `Read` → Read, `Write`/`Edit` → Edit, `Grep`/`Glob` → Grep, `Task` → Task, `MCP:*` → MCP). Nieznane nazwy dają zwykłe „pracuje”. Mapę potwierdzamy nagraniem (8).
- **Tekst akcji:** `action_from` z białą listą kluczy `tool_input` (`command`, `file_path`/`path`, `pattern`, `url`, `query`).
- **Nigdy nie czytamy:** `prompt`, `attachments`, `user_email`, `transcript_path`, `workspace_roots` ani wyniku narzędzia.
- **Program:** `Cursor.exe` → `App::Cursor` (jest od 0.10), `cursor-agent` w terminalu → program terminala.

### 3.3 Grok Build: instalacja

- **Plik:** nasz własny `~/.grok/hooks/agent-pets.json`.
- **Schemat:** `{"hooks":{"<Zdarzenie>":[{"matcher":"*","hooks":[{"type":"command","command":"\"<hook.exe>\" --agent grok --event <Zdarzenie>","timeout":5}]}]}}`; `matcher` tylko przy zdarzeniach narzędzi.
- **Zdarzenia:** `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `Notification`, `Stop`, `StopFailure`, `PreCompact`.
- **Włączenie:** zapis atomowy. **Wyłączenie:** usuwa nasz plik; cudze pliki w `hooks/` nietknięte.
- **Wykrycie:** jest katalog `~/.grok`. Bez niego włączenie odmawia.

### 3.4 Grok Build: tłumaczenie

Id sesji: `sessionId` (także z `GROK_SESSION_ID`, 2.1), `safe_id`. Model: pole `model`, jeśli Grok je wysyła (8).

| Zdarzenie | Stan sklepu |
|---|---|
| `SessionStart` | SessionStart |
| `UserPromptSubmit` | Prompt |
| `PreToolUse` | ToolStart |
| `PostToolUse` | ToolEnd |
| `PostToolUseFailure`, przerwanie (pole ustalone nagraniem) | TurnEnd |
| `PostToolUseFailure`, pozostałe | ToolEnd |
| `Notification` rozpoznane jako pytanie o zgodę | NeedsInput |
| `Notification`, pozostałe | bez zmiany |
| `Stop` | TurnEnd |
| `StopFailure` | Error |
| `PreCompact` | Compact |
| `SessionEnd` | SessionEnd |

- **Narzędzia:** dokumentacja nie podaje nazw. Mapa po słowach kluczowych w nazwie (`bash`/`shell`/`exec` → Bash, `read` → Read, `write`/`edit`/`patch` → Edit, `grep`/`search`/`glob` → Grep, `web`/`fetch` → WebFetch). Nazwy potwierdzamy nagraniem.
- **Tekst akcji:** biała lista kluczy `toolInput`, jak w 3.2.
- **Nigdy nie czytamy:** promptu, wiadomości asystenta, wyniku narzędzia ani ścieżki transkryptu.
- **Program:** Grok działa w terminalu → program terminala.

### 3.5 ZCode: instalacja

- **Plik:** konfiguracja użytkownika ZCode `~/.zcode/cli/config.json` (albo `$ZCODE_DATA_BASE_DIR/cli/config.json`, gdy widżet ma tę zmienną), klucz `hooks`.
- **Schemat pliku (sprawdzony w bundlu ZCode i na żywo, 0.12):** `{"hooks": {"enabled": true, "events": {...}}}`. Obok `events` ZCode przyjmuje tylko `enabled`, `timeoutMs` i `maxOutputBytes`; inny klucz w `hooks` (np. zdarzenie wprost) unieważnia cały plik. Bez `enabled: true` ZCode nie uruchamia żadnego hooka.
- **Schemat wpisu:** `hooks.events.<Zdarzenie>: [{"matcher":"*","hooks":[{"type":"process","command":"<hook.exe>","args":["--agent","zcode","--event","<Zdarzenie>"],"timeoutMs":5000}]}]`. Typ `process` uruchamia program bez powłoki, więc ścieżka nie wymaga cudzysłowów.
- **Zdarzenia:** `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PostToolUseFailure`, `Stop`.
- **Włączenie:** dopisanie do cudzej zawartości:
  - przed pierwszą zmianą kopia `config.json.agent-pets-backup`;
  - nasze wpisy rozpoznajemy po `command` z naszą ścieżką i `args` z `zcode`; ponowne włączenie ich nie dubluje;
  - zły JSON albo nietypowy kształt `hooks` → odmowa bez zmian;
  - ustawiamy `hooks.enabled: true`; jawne `false` użytkownika → odmowa bez zmian;
  - zapis atomowy, pozostałe klucze pliku bez zmian.
- **Wyłączenie:** usuwa tylko nasze wpisy, puste tablice zdarzeń, pusty `events`, nasze `enabled` (zostaje, gdy było w kopii sprzed naszej zmiany) i pusty klucz `hooks`.
- **Wykrycie:** jest katalog `~/.zcode` (albo `ZCODE_DATA_BASE_DIR`). Bez niego włączenie odmawia.

### 3.6 ZCode: tłumaczenie

ZCode wysyła pola w camelCase i ich odpowiedniki z Claude Code. Adapter przyjmuje oba zapisy: `sessionId`/`session_id`, `toolName`/`tool_name`, `toolInput`/`tool_input`. Id sesji przez `safe_id`. Model: `model` z `SessionStart` → `Meta`.

| Zdarzenie | Stan sklepu |
|---|---|
| `SessionStart` | SessionStart |
| `UserPromptSubmit` | Prompt |
| `PreToolUse` | ToolStart |
| `PermissionRequest` | NeedsInput (pytanie = tekst akcji narzędzia; pola `reason` nie pokazujemy) |
| `PostToolUse` | ToolEnd |
| `PostToolUseFailure`, `isInterrupt: true` | TurnEnd |
| `PostToolUseFailure`, pozostałe | ToolEnd |
| `Stop` | TurnEnd |

- **Brak zdarzenia błędu i końca sesji:** po błędzie zwierzak wraca do bezczynności po 10 min, jak przy każdej ciszy; sesja znika jak sesje Copilota bez końca.
- **Narzędzia:** mapa po słowach kluczowych jak w 3.4, potwierdzona nagraniem.
- **Program:** aplikacja ZCode → nowe `App::Zcode` (nazwa pliku `.exe` ustalona na żywo), CLI → program terminala.

## 4. Kolejność w `hook.exe`

1. Czytanie JSON-a z wejścia (zły JSON → nic nie wysyłamy, ale wyjście z 2.1 zawsze jest wypisane).
2. `caller` (2.2): cudze wywołanie → koniec bez wysyłki.
3. Dla Groka uzupełnienie `sessionId` (2.1).
4. Program-gospodarz, jeśli `host_event`.
5. Wysyłka koperty.
6. Wyjście wymagane przez agenta (Cursor, Antigravity).

## 5. Model danych

- `Agent` dostaje `Zcode` (nazwa `zcode`). `Cursor` i `Grok` już są.
- `generic::RESERVED` dostaje `zcode`.
- `agent_on` sprawdza przełączniki Cursora, Groka i ZCode zamiast stałego `false`.
- `SubKind` dostaje `Cursor`.
- `integrations::AppId` dostaje `Cursor`, `Grok`, `Zcode`: wykrycie, stan, włączenie, wyłączenie.
- `settings::Apps` i `Overrides` dostają `cursor`, `grok`, `zcode`, wszystkie domyślnie `false`. Stare pliki ustawień wczytują się bez zmian.
- **Naprawa przy starcie** (`repair_integrations`): obejmuje trzy nowe integracje (włączona → wpisy na miejscu, z aktualną ścieżką).
- **Trasy:** `/v1/events/cursor`, `/v1/events/grok`, `/v1/events/zcode`; ten sam token i limit rozmiaru; wyłączona integracja → 404.
- `host::App` dostaje `Zcode`.
- **TS:** `Agent` dostaje `'zcode'`, i18n nazw w obu językach.

## 6. Wygląd

Decyzje użytkownika: Cursor i Grok jak w propozycji, ZCode jako panda. Szczegóły zatwierdzane na podglądzie (`looks-dev`, vite na porcie 1430) przed wydaniem; jak przy Copilocie, pokazujemy warianty i użytkownik wybiera.

| Agent | Postać | Kolory | Ruch |
|---|---|---|---|
| Cursor | kryształowy graniastosłup ze ściętymi krawędziami; jaśniejsza przednia ściana z oczami | czerń i biel, jasnoszary akcent | chodzi jak inni |
| Grok | ciemna kula przecięta ukośną kreską (nawiązanie do logo) z zadziornymi oczami (skośne brwi) | prawie czarne ciało, biała kreska | chodzi jak inni |
| ZCode | panda: białe ciało, czarne uszy i łaty wokół oczu, opaska na głowie z małym „Z” (nawiązanie do Pekinu, siedziby Zhipu AI) | czerń i biel, akcent opaski w kolorze Z.ai (niebieski) | chodzi jak inni |

- `SkinId`, `ACCENT`, `skinFor` dostają trzy postacie; zastępują dzisiejszego bloba dla Cursora i Groka (`sceneFor.ts`).
- Pixel i Sticker rysują je jak Clean (`effectiveStyle`, jak w 0.10 i 0.11).
- Oczy nad biurkiem przy pisaniu, jak u Copilota w 0.11.

## 8. Sprawdzenia na żywo

Użytkownik nie ma subskrypcji Cursora, Groka ani ZCode (decyzja: „Cursor + to, co się da”). Instaluje wszystkie trzy:
- Cursor z cursor.com, darmowy plan Hobby (kilka darmowych zapytań);
- Grok Build: `irm https://x.ai/cli/install.ps1 | iex`;
- ZCode: instalator `ZCode-3.14.3-win-x64.exe` z wydań github.com/zai-org/ZCode.

Nagrywanie jak w 0.11: tymczasowy hook zapisuje koperty do pliku w scratchpadzie; do fixtures trafiają po anonimizacji (teksty → `…`, id → stałe). Kopia konfiguracji przed każdą zmianą.

1. **Cursor:**
   - która ścieżka `hooks.json` działa i czy komenda z cudzysłowami się uruchamia;
   - sesja przechodzi przez stany, nazwy narzędzi, podpis „· Cursor”, skok do okna;
   - `{}` przy `preToolUse` nie zmienia pytań o zgodę, `{"continue":true}` nie zmienia wysyłania promptu;
   - z włączoną integracją Claude Code nie ma ducha Claude'a (Cursor czyta hooki Claude'a).
2. **Grok Build:** co się da bez subskrypcji (start sesji, prompt, błąd logowania albo zapytania):
   - czy plik w `~/.grok/hooks` działa, czy `GROK_HOOK_EVENT` jest ustawione;
   - brak ducha Claude'a i ducha Cursora;
   - nazwy narzędzi i `Notification`, jeśli uda się dojść do narzędzia.
3. **ZCode:** jak Grok; do tego czy aplikacja nie nadpisuje naszych wpisów w `config.json`, nazwa `.exe` aplikacji, czy ZCode wysyła `hookEventName` i ustawia `ZCODE_SESSION_ID`.
4. **Regresja priorytetów:** Claude Code, Codex i opencode działają jak w 0.11 (warunek wydania).

Czego nie da się sprawdzić, zostaje oznaczone jako eksperymentalne w ustawieniach i README; ruling w ledgerze.

## 9. Prywatność i bezpieczeństwo

- **Sieć:** bez nowych połączeń poza 127.0.0.1. Nie łączymy się z serwerami Cursora, xAI, Z.ai ani Google.
- **Koperty:** przekazujemy tylko stan, rodzaj narzędzia, krótki tekst akcji z białej listy, pytanie przy `needs_you` i nazwę modelu. Nigdy promptu, załączników, e-maila (`user_email` w Cursorze), odpowiedzi, wyniku narzędzia ani ścieżki transkryptu.
- **Pliki konfiguracyjne agentów:** zmieniamy tylko za zgodą; plik wspólny (Cursor, ZCode) z kopią i usuwaniem wyłącznie naszych wpisów, plik własny (Grok) usuwany w całości.
- **Zachowanie agentów bez zmian:** żadnych decyzji o zgodzie, blokad promptu ani wiadomości dla modelu.
