# Agent Pets 0.11: Copilot, Antigravity i zużycie opencode

Status: projekt zatwierdzony w rozmowie z 2026-09-27, do przeczytania przez użytkownika. Rozwija wydanie 0.11 z programu `2026-09-27-agent-pets-more-agents-design.md` (dalej „spec 0.10”) i dokłada zużycie opencode, o które użytkownik poprosił po teście 0.10. Wyniki rozpoznania: `docs/0.11-spikes.md`.

## 1. Cel

1. **GitHub Copilot** jako agent z własnym zwierzakiem: Copilot CLI, tryb agenta w VS Code i w JetBrains (plugin od 06.2026 uruchamia agenta przez Copilot CLI).
2. **Antigravity** jako agent z własnym zwierzakiem: IDE, aplikacja 2.0 i CLI `agy`, w wersjach z hookami.
3. **Zużycie opencode** (decyzja użytkownika: „A, B i C”):
   - A: tokeny sesji i dnia na karcie opencode w panelu, koszt w $ tylko gdy większy od 0;
   - B: opencode w oknie statystyk jako trzeci agent;
   - C: paski limitów konta Claude'a albo Codexa na karcie opencode, gdy opencode korzysta z tej subskrypcji.

Poza zakresem:
- Cursor i Grok Build (0.12), kolejka z spec 0.10 §1;
- limity i statystyki Copilota i Antigravity (ich hooki nie niosą tokenów);
- paski limitów dla innych dostawców opencode (`zai-coding-plan` i pozostali): wymagałyby zapytania do ich serwerów z tokenem użytkownika, a tego nie robimy (9);
- mini zwierzaki podagentów Antigravity (hooki nie wiążą rozmowy podagenta z rodzicem);
- stan „czeka na Ciebie” w Antigravity (decyzja użytkownika: ograniczone stany, 3.3);
- odtwarzanie sesji Copilota i Antigravity po restarcie widżetu (jak w 0.10: wracają przy pierwszym zdarzeniu).

## 2. Wspólny szkielet dla hooków

Rozszerza spec 0.10 §4.1.

- **Wywołanie:** `hook.exe --agent <copilot|antigravity> --event <nazwa>`. Nazwę zdarzenia bierzemy z argumentu, nie z JSON-a: Antigravity nie przysyła jej wcale, a Copilot tylko przy części zdarzeń.
- **Działanie `hook.exe`:**
  - czyta JSON z wejścia;
  - dokleja `ts`, PID agenta i nazwę zdarzenia;
  - dokleja program (drzewo procesów z 0.10, jeden zrzut) tylko przy zdarzeniach początku tury: Copilot `SessionStart` i `UserPromptSubmit`, Antigravity `PreInvocation`. `hook.exe` nie ma stanu, więc to runtime pamięta program sesji (jak `opencode_hosts`);
  - wysyła kopertę na `/v1/events/<agent>`.
- **Zasady jak dziś:** limit 300 ms, kod wyjścia 0, ciche błędy.
- **Wyjście:** jedyna różnica to to, co hook wypisuje, bo oba programy czytają odpowiedź:
  - Copilot: nic (pusta odpowiedź i kod 0 = hook bez zdania, Copilot robi swoje);
  - Antigravity: `{}` dla `PreInvocation`, `PreToolUse`, `PostToolUse`, `PostInvocation`; `{"decision":"stop"}` dla `Stop`.
  - Nigdy `continue`: Antigravity przy `continue` nie kończy pracy.
  - Nigdy decyzji o zgodzie: nie zmieniamy zachowania agentów.
- **Stała ścieżka:** oba pliki konfiguracyjne wskazują na `~/.agent-pets/hook.exe`, kopię trzymaną przez aplikację (jak przy furtce w 0.10). `place_hook` działa, gdy włączona jest furtka, Copilot albo Antigravity.
- **Rdzeń:** `adapters/copilot.rs` i `adapters/antigravity.rs` to czyste funkcje: koperta → zdarzenia sklepu. Są testowane na fixtures z zapisanych prawdziwych kopert, z tekstami zastąpionymi przez `…`.
- **Endpoint:** trasy `/v1/events/copilot` i `/v1/events/antigravity`, ten sam token i limit rozmiaru. Trasa wyłączonej integracji zwraca 404 (jak furtka).

## 3. Agenci

### 3.1 Copilot: instalacja

- **Plik:** nasz własny `~/.copilot/hooks/agent-pets.json` (Windows: `%USERPROFILE%\.copilot\hooks\`). Czytają go Copilot CLI i VS Code (katalog użytkownika z hookami). JetBrains z harnessem Copilot CLI czyta go przez CLI; sprawdzimy na żywo (8).
- **Nazwy zdarzeń w pliku:**
  - PascalCase dla zdarzeń znanych VS Code: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `SubagentStart`, `SubagentStop`, `Stop`;
  - camelCase dla zdarzeń tylko z CLI: `sessionEnd`, `notification`, `errorOccurred`, `postToolUseFailure`;
  - każde zdarzenie wpisane raz.
- **Klucze komendy:** `powershell` i `command` z tą samą komendą, `timeoutSec: 5`, `version: 1`.
- **Włączenie:** zapis atomowy.
- **Wyłączenie:** usuwa nasz plik; cudze pliki w `hooks/` nietknięte.
- **Wykrycie:** jest katalog `~/.copilot`. Bez niego włączenie odmawia (jak opencode bez `~/.config/opencode`).

### 3.2 Copilot: tłumaczenie

Adapter przyjmuje oba zapisy pól: `session_id`/`sessionId`, `tool_name`/`toolName`, `tool_input`/`toolArgs`, `transcript_path`/`transcriptPath`, `cwd`. Brak id sesji oznacza, że zdarzenie jest pomijane.

| Zdarzenie | Stan sklepu |
|---|---|
| `SessionStart` | start sesji (`idle`), program z koperty |
| `UserPromptSubmit` | `working`, bez tekstu promptu |
| `PreToolUse` | `working` z narzędziem i tekstem akcji: plik, komenda, wzorzec z białej listy argumentów jak w opencode |
| `PostToolUse`, `postToolUseFailure` | `working` |
| `notification`, `notification_type` = `permission_prompt` albo `elicitation_dialog` | `needs_you`, pytanie = `message` albo `title` (przycięte, bez znaków sterujących) |
| `notification`, pozostałe typy | bez zmiany stanu |
| `Stop` | `done` |
| `errorOccurred` | `error`, gdy `recoverable` nie jest `true`; inaczej bez zmiany |
| `sessionEnd` | `ended` |
| `SubagentStart` / `SubagentStop` | dziecko sesji (`SubKind::Copilot`), mini zwierzak jak u Claude'a; id dziecka z `agentId` albo z `agentName` + numeru kolejnego |

- **Id sesji:** `copilot:<sessionId>`.
- **Model:** z pola `model`, gdy koperta go ma. Dokumentacja go nie wymienia, więc bez modelu podpis to „Copilot · program”.
- **Program:** z drzewa procesów:
  - `idea64.exe` i rodzina → JetBrains;
  - `Code.exe` → VS Code;
  - inaczej terminal.
- **Skok:** okno programu, a w terminalu okno terminala. Wznowienia nie ma: schowek dostaje tylko `cd`, jak u agentów bez wznowienia w 0.10.

### 3.3 Antigravity: instalacja

- **Plik:** `~/.gemini/config/hooks.json`, mapa „nazwa hooka → zdarzenia”. Dopisujemy jeden klucz `agent-pets` ze zdarzeniami `PreInvocation`, `PreToolUse` (matcher `*`), `PostToolUse` (matcher `*`) i `Stop`, `timeout: 5`. Cudze klucze zostają nietknięte.
- **Przed pierwszą zmianą:** kopia pliku w `~/.agent-pets/backup/`.
- **Plik nie jest poprawnym JSON-em:** nie zmieniamy go i zgłaszamy błąd w ustawieniach.
- **Wyłączenie:** usuwa tylko klucz `agent-pets`. Jeśli plik utworzyliśmy my i został pusty (`{}`), usuwamy go.
- **Wykrycie:** jest katalog `~/.gemini`. Bez niego włączenie odmawia. Katalog `config` tworzymy, gdy go brak.
- **Starsze wersje bez hooków** (np. IDE 1.107 u użytkownika) po prostu nie wołają hooka. Ustawienia mówią, że potrzebna jest wersja z hookami.

### 3.4 Antigravity: tłumaczenie

Pola: `conversationId`, `workspacePaths[0]` jako `cwd`, `modelName`, `toolCall.name`, `toolCall.args`, `terminationReason`, `error`, `fullyIdle`.

| Zdarzenie | Stan sklepu |
|---|---|
| pierwsze zdarzenie rozmowy | start sesji (bez sztucznego `SessionStart` w zapisie, jak furtka) |
| `PreInvocation` | `working` bez narzędzia (myśli) |
| `PreToolUse` | `working` z narzędziem i tekstem akcji z białej listy argumentów |
| `PostToolUse` | `working` |
| `Stop`, `terminationReason` = `error` albo niepusty `error` | `error` |
| `Stop`, `fullyIdle` = `true` | `done` |
| `Stop`, `fullyIdle` = `false` | `working` (pracują jeszcze podagenci) |

- **Id sesji:** `antigravity:<conversationId>`.
- **Model:** `modelName`.
- **Program:** `Antigravity.exe` → Antigravity; `agy` w terminalu → terminal.
- **Koniec:** sesja zasypia i kończy się według progów bezczynności z 0.10 albo gdy proces agenta zniknie.
- **Brak „czeka na Ciebie”:** Antigravity nie ma zdarzenia prośby o zgodę. README to opisuje.
- **Mapa narzędzi (nieznane → `other`):**
  - `run_command` → bash;
  - `view_file`, `list_dir` → read;
  - `write_to_file`, `replace_file_content`, `multi_replace_file_content` → edit;
  - `grep_search`, `find_by_name` → grep;
  - `read_url_content`, `search_web`, `browser_*` → web;
  - `invoke_subagent` → agent.

## 4. Zużycie opencode

### 4.1 Odczyt bazy

- **Plik:** `~/.local/share/opencode/opencode.db` (SQLite w trybie WAL). Moduł `pets-core/src/opencode_db.rs` na `rusqlite` (wbudowany SQLite).
- **Otwieranie:**
  - tylko do odczytu (`SQLITE_OPEN_READ_ONLY`), `busy_timeout` 200 ms;
  - połączenie otwierane na jedno odczytanie i zamykane (nie trzyma blokad);
  - błąd otwarcia albo zapytania oznacza brak danych, bez komunikatu.
- **Prywatność** (baza ma też tabele z tokenami logowania: `credential`, `account`, `control_account`):
  - zapytania dotykają wyłącznie tabel `session`, `message` i `part`;
  - z kolumny `data` czytamy tylko wybrane pola przez `json_extract`, nigdy całą kolumnę;
  - dozwolone ścieżki:
    - `message`: `$.role`, `$.providerID`, `$.modelID`, `$.cost`, `$.tokens.input`, `$.tokens.output`, `$.tokens.reasoning`, `$.tokens.cache.read`, `$.tokens.cache.write`, `$.time.created`, `$.time.completed`, `$.path.cwd`;
    - `part`: `$.type`, `$.tool`.
  - Wszystkie zapytania są stałymi w jednym miejscu, a test sprawdza każde z nich pod kątem listy tabel i ścieżek.
- **Kiedy czytamy:**
  - A i C: co 30 s, gdy istnieje choć jeden zwierzak opencode, oraz po każdym `done` opencode;
  - B: skaner statystyk (4.4).
- **Warunek:** integracja opencode jest włączona. Przy wyłączonej nie czytamy bazy wcale.

### 4.2 A: tokeny na karcie

- **Sesja:** suma kolumn `tokens_input`, `tokens_output`, `tokens_reasoning`, `tokens_cache_read` i `tokens_cache_write` oraz `cost` z wiersza `session` (id bez prefiksu `opencode:`). Podagenci są osobnymi wierszami; karta rodzica pokazuje tylko jego własne zużycie.
- **Dziś:** suma tokenów i kosztu wiadomości `assistant` od lokalnej północy, ze wszystkich sesji opencode.
- **Snapshot:**
  - `Session.usage: Option<{ tokens: u64, cost: f64, account: Option<Agent> }>` dla sesji opencode;
  - `Snapshot.agent_usage: [{ agent: 'opencode', tokens_today, cost_today }]`.
- **Karta w panelu:** linia „sesja: 1,2 mln tok. · dziś: 4,8 mln tok.”. Koszt („· $0,42”) tylko wtedy, gdy jest większy od 0. Liczby w formacie z okna statystyk. Tooltip bez zmian.

### 4.3 C: paski konta

- **Konto sesji:** bierzemy ostatnią wiadomość `assistant` tej sesji.
  - `providerID` = `openai` → konto Codex;
  - `providerID` = `anthropic` → konto Claude.
  - W obu przypadkach tylko wtedy, gdy koszt sesji to 0 przy tokenach większych od 0. Zero przy prawdziwym zużyciu znaczy subskrypcję; przy kluczu API opencode liczy koszt.
  - Inaczej `account: None`.
- **Karta opencode:** pod linią zużycia te same dwa paski (5 h, tydzień) co w sekcji limitów panelu dla wskazanego konta, z tych samych danych (`Snapshot.limits`).
- **Bez danych o limitach tego konta:** pasków nie ma (nie pokazujemy 0%).
- **Czego nie robimy:** nie czytamy `auth.json` ani tabel z tokenami, więc nie rozróżniamy subskrypcji inaczej niż po koszcie. Pomyłka (np. darmowy model `openai` przez klucz) pokaże paski Codexa; skutek jest tylko wizualny.

### 4.4 B: statystyki

- **`StatAgent`** dostaje `Opencode`.
- **Pozycje w księdze:** każda sesja opencode to jedna pozycja w `Book.files` pod kluczem `opencode:<id sesji>`. Kubełki i pola są jak dziś:
  - tokeny: `input`, `cache_read`, `cache_write`, `output + reasoning`;
  - model = `modelID`, projekt = nazwa folderu `$.path.cwd`;
  - czas pracy z czasów wiadomości `assistant` według `GAP_MS`;
  - pytania = wiadomości `user`;
  - narzędzia z części `part` typu `tool` według tej samej mapy nazw co adapter opencode.
- **Przyrostowo:** skaner pamięta najwyższe `message.time_updated` i przelicza od zera tylko sesje z nowszymi wiadomościami. Pierwsze przejście czyta całą historię w tle, z tym samym budżetem i pauzą co pliki Claude'a i Codexa.
- **Okno statystyk:** opencode wszędzie tam, gdzie dziś są Claude, Codex i router: filtry, podium, wyścig, kalendarz, odznaki. Kolor = akcent opencode.

## 5. Model danych

- `SubKind` dostaje `Copilot`.
- `integrations::AppId` dostaje `Copilot` i `Antigravity`: wykrycie, stan, włączenie i wyłączenie jak opencode.
- `settings::Apps` dostaje `copilot` i `antigravity`, oba domyślnie `false`. Stare pliki ustawień wczytują się bez zmian.
- **Naprawa przy starcie** (`repair_integrations`): obejmuje oba pliki hooków, tak jak plugin opencode (włączona integracja → plik na miejscu).
- `Overrides` dostaje `copilot` i `antigravity`.
- **TS:** lustro nowych pól jako opcjonalne (`usage?`, `agent_usage?`).

## 8. Sprawdzenia na żywo

Z użytkownikiem, przed wydaniem:

1. **Copilot w IntelliJ:** włączenie, sesja przechodzi przez stany, prośba o zgodę daje dymek, podpis „· JetBrains”, skok do okna IntelliJ.
   - Nagrane koperty trafiają do fixtures.
   - Jeśli IntelliJ nie woła hooków z `~/.copilot/hooks`: ruling i opis w README (działa CLI i VS Code).
2. **Antigravity po aktualizacji:** stany, model w tooltipie.
   - Sprawdzamy, że `{}` przy `PreToolUse` nie zmienia pytań o zgodę, a `Stop` kończy pracę normalnie.
   - Tego nie da się sprawdzić bez prawdziwego programu, więc to warunek wydania.
3. **opencode:** tokeny sesji i dnia zgodne z bazą, paski Codexa przy dostawcy `openai`, opencode w statystykach.

## 9. Prywatność i bezpieczeństwo

- **Sieć:** bez nowych połączeń poza 127.0.0.1. Nie łączymy się z serwerami Copilota, Google, opencode ani z.ai.
- **Koperty:** Copilot i Antigravity przekazują tylko stan, rodzaj narzędzia, krótki tekst akcji z białej listy, pytanie przy `needs_you` i nazwę modelu. Nigdy promptu, odpowiedzi, wyniku narzędzia (`toolResult`, `response`) ani ścieżki transkryptu.
- **Baza opencode:** tylko do odczytu, tylko pola z 4.1. Nigdy `auth.json` ani tabele z tokenami.
- **Pliki konfiguracyjne agentów:** zmieniamy tylko za zgodą, z kopią (Antigravity) albo we własnym pliku (Copilot), z pełnym wyłączeniem.
