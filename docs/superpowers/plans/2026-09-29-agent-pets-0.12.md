# Agent Pets 0.12.0 (Cursor, Grok Build, ZCode). Plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Cel:** zwierzaki dla Cursora, Grok Build i ZCode (hooki → `hook.exe`); `hook.exe` odrzuca wywołania obcych agentów, żeby nie było duchów Claude'a; README mówi, na czym się skupiamy.

**Architektura:**
- **Rdzeń:**
  - `Source::{Cursor, Grok, Zcode}`, `Agent::Zcode`, `SubKind::Cursor`, `App::Zcode`;
  - `adapters::{cursor, grok, zcode}` (koperta → zdarzenia);
  - `adapters::caller` (kto naprawdę wywołał hook) i `adapters::slim` (odchudzenie koperty);
  - trzy nowe drzwi i trasy;
  - integracje: dopisanie do wspólnego `hooks.json` Cursora, własny plik Groka, dopisanie do `config.json` ZCode.
- **hook.exe:** tryb `--agent` dla `cursor|grok|zcode`, odrzucanie obcych w obu trybach, `{"continue":true}`/`{}` dla Cursora, `sessionId` Groka ze zmiennej.
- **Aplikacja:** przełączniki z plakietką „eksperymentalne”, naprawa przy starcie, kreator, skok do okna.
- **Front:** skiny `cursor` (graniastosłup), `grok` (kula z kreską), `zcode` (panda z opaską „Z”).

**Stos:** jak w 0.11 (Tauri 2, React/TS, vitest, Rust workspace). Bez nowych zależności.

**Specyfikacja:** `docs/superpowers/specs/2026-09-29-agent-pets-0.12-design.md` (wiąże).

## Global Constraints

- **Z wcześniejszych wersji obowiązuje:**
  - TDD;
  - teksty w UI tylko przez JSX albo `textContent`;
  - skan i18n (brak polskich literałów poza `i18n/pl.ts`);
  - `settings.json` i zapisane sesje z 0.11 wczytują się bez zmian (`#[serde(default)]` na każdym nowym polu; TS: nowe pola opcjonalne).
- **Priorytet:** Claude Code, Codex i opencode działają jak w 0.11 (warunek wydania). Cursor, Grok i ZCode: co nie sprawdzone na żywo, wychodzi jako eksperymentalne.
- **Hook nigdy nie blokuje agenta:**
  - limit łączenia 150 ms, całość 300 ms;
  - zawsze kod 0;
  - wyjście tylko takie, jakiego wymaga agent: Cursor `{"continue":true}` przy `beforeSubmitPrompt`, `{}` przy reszcie; Grok i ZCode nic; Copilot i Antigravity jak w 0.11;
  - wyjście wypisane także przy złym JSON-ie, wyłączonym widżecie i odrzuconym obcym wywołaniu.
- **Nigdy nie zmieniamy decyzji agentów:** żadnych pól `permission`, `followup_message`, `user_message`, `decision`, `continue: false`.
- **Prywatność:**
  - adaptery przekazują tylko stan, rodzaj narzędzia, krótki tekst akcji z białej listy, pytanie przy `needs_you`, id modelu i program;
  - nigdy `prompt`, `attachments`, `user_email`, `transcript_path`, `workspace_roots`, wyniku narzędzia, odpowiedzi modelu;
  - `hook.exe` w trybie `--agent` usuwa te pola z koperty przed wysłaniem (`slim`, task 2).
- **Pliki agentów:** tylko przez integracje (zgoda w kreatorze/ustawieniach).
  - Cursor: nasze wpisy w tablicach zdarzeń `hooks.json`; ZCode: nasze wpisy pod kluczem `hooks` w `config.json`; oba przez `hooks_install::edit_file_opts` (zapis atomowy, zły JSON = błąd bez zapisu).
  - Grok: nasz plik `~/.grok/hooks/agent-pets.json`, cudzego o tej nazwie nie nadpisujemy.
  - **Ruling planu wobec spec §3.1 i §3.5:** kopia to `<plik>.agent-pets.bak` obok pliku (mechanizm `edit_file_opts` z 0.10/0.11), a nie `hooks.json.agent-pets-backup` / `config.json.agent-pets-backup`. Ten sam sprawdzony mechanizm; koszt pomyłki: inna nazwa pliku kopii.
- **Sieć:** tylko 127.0.0.1. Żadnych połączeń z serwerami Cursora, xAI, Z.ai ani Google z aplikacji.
- **Push, merge i wydanie** tylko po zgodzie użytkownika; skan prywatnych danych i push w osobnych krokach.
- **Edycje skryptami:**
  - Python z pliku zapisanego narzędziem Write, `newline=''`, `PYTHONIOENCODING=utf-8`;
  - backslashe tylko przez Write/Edit;
  - LF;
  - grep diffu pod kątem `uid=` i nazwy użytkownika przed commitem.
- **Build:** `CARGO_BUILD_JOBS=6`. Bez okien i bez buildów release przy grze na pełnym ekranie (`SHQueryUserNotificationState` ≠ 5).
- **Bramka testów:** `cargo test --workspace` i `pnpm --dir app test --testTimeout=30000`, oba z kodem wyjścia.

## Review Focus

1. **Claude Code uruchomiony w terminalu Cursora, Groka albo ZCode.**
   - Odziedziczone zmienne (`ZCODE_SESSION_ID`, `GROK_SESSION_ID`, `CURSOR_*`) nie mogą odebrać użytkownikowi zwierzaka Claude'a.
   - Test `caller` w tasku 2:
     - JSON Claude'a (`hook_event_name`, bez `cursor_version`) z `ZCODE_SESSION_ID` → brak;
     - z `GROK_SESSION_ID`, ale bez `GROK_HOOK_EVENT` → brak;
     - tryb Claude wysyła.
2. **Duży albo ciężki payload Cursora** (`beforeSubmitPrompt` z załącznikami > 1 MB, `postToolUse` z wielkim wynikiem).
   - Zwierzak dalej dostaje zdarzenie, bo `slim` usuwa ciężkie pola przed limitem 1 MB trasy.
   - Hook wypisuje `{"continue":true}` w < 1 s.
   - Testy w tasku 2.
3. **Ścieżka domowa ze spacją i apostrofem** (`C:\Users\Jan Kowalski`, `C:\Users\O'Neil`).
   - Komenda Cursora i Groka musi się uruchomić.
   - `command` ZCode (typ `process`) to goła ścieżka bez cudzysłowów, a argumenty są osobno w `args`.
   - Test budowania wpisów w tasku 6.
4. **Nietypowy `hooks.json` Cursora albo `config.json` ZCode:**
   - korzeń nie jest obiektem, `hooks` nie jest obiektem, wartość zdarzenia nie jest tablicą → odmowa bez zmian, z komunikatem;
   - cudze wpisy w tej samej tablicy zdarzenia zostają przy włączeniu i wyłączeniu;
   - inne klucze `config.json` ZCode zostają bajt w bajt co do treści (porównanie `Value`);
   - ponowne włączenie po zmianie ścieżki `hook.exe` podmienia nasz wpis zamiast dokładać drugi.

   Testy w tasku 6.
5. **Grok czytający hooki Cursora i Claude'a** przy włączonych wszystkich integracjach:
   - jedno zdarzenie Groka daje jednego zwierzaka Groka, a nie trzy (Grok + Cursor + Claude);
   - wywołanie Cursora z `GROK_HOOK_EVENT` dalej wypisuje `{}`, bo Grok może czekać na wyjście w formacie Cursora.

   Testy w tasku 2.
