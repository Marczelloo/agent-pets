# Agent Pets 0.9.0 (statystyki). Plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Cel:** okno „Statystyki” z podium projektów, kafelkami, wyścigiem, kalendarzem aktywności i odznakami. Liczby pochodzą z historii transkryptów Claude Code i rolloutów Codexa, liczone w tle i zapisywane lokalnie.

**Architektura:**
- **Rdzeń:** nowy moduł `stats`:
  - ekstraktory linii (Claude, Codex) zapisują wkład każdego pliku w kubełki **godzina UTC × model**;
  - księga (`stats.json`) trzyma wpis na plik: kursor, metadane, wkład;
  - skaner czyta historię od najnowszych plików i potem tylko dopisane bajty;
  - `summary` składa widok, a przesunięcie strefy czasowej dostaje z zewnątrz.
- **Aplikacja:**
  - wątek skanu o niskim priorytecie z pauzą przy pełnym ekranie;
  - okno `stats`, komenda `stats_view`, zdarzenie postępu;
  - wejście z panelu i z menu zasobnika.
- **Front:**
  - strona `stats.html` (React) z podium, licznikami, wyścigiem, kalendarzem i odznakami;
  - nowe sceny zwierzaków (podium, bieg) i rzeczy „na sobie” dla odznak we wszystkich modelach rysowania.

**Stos:** jak w 0.8 (Tauri 2, React/TS, vitest, Rust workspace).

**Specyfikacja:** `docs/superpowers/specs/2026-09-27-agent-pets-0.9-stats-design.md` (wiąże).

## Global Constraints

- **Z wcześniejszych wersji obowiązuje:**
  - testy przed kodem (TDD) i przed commitem;
  - teksty w UI tylko przez JSX albo `textContent`;
  - skan i18n (brak polskich literałów poza `i18n/pl.ts`);
  - okno pokazane przez Win32 chowane też przez Win32;
  - `settings.json` z 0.8 musi działać bez zmian.
- **Prywatność:**
  - `stats.json` zawiera wyłącznie liczby, godziny, nazwy folderów projektów (ostatni człon `cwd`), nazwy modeli, ścieżki przeczytanych plików i id sesji;
  - nigdy treść wiadomości, komendy, nazwy plików, nad którymi pracował agent, ani tytuły sesji;
  - nazwy projektów i ścieżki nie trafiają do raportu diagnostycznego ani do logów (`eprintln!`).
- **Obciążenie:**
  - skan czyta pliki linia po linii (`BufRead`), nigdy całego pliku do pamięci;
  - wątek skanu ma niski priorytet;
  - skan stoi, gdy `shell::fullscreen_app()` zwraca `true`.
- **Push i wydanie** tylko po zgodzie użytkownika; skan prywatnych danych i push w osobnych krokach.
- **Edycje skryptami:**
  - Python z pliku zapisanego narzędziem Write, bez `python -c` z backtickami;
  - backslashe tylko przez narzędzie Write albo Edit (heredoc je psuje);
  - LF;
  - grep diffu pod kątem `uid=` i nazwy użytkownika przed commitem.
- **Build:** `CARGO_BUILD_JOBS=6`. Bez okien na ekranie i bez buildów release, gdy działa gra na pełnym ekranie (sprawdzenie `SHQueryUserNotificationState`).
- **Bramka testów:** `cargo test --workspace` i `pnpm --dir app test --testTimeout=30000`, oba z kodem wyjścia (bez `| tail`, które go gubi).

Zasady ze specyfikacji 3.1:

- **Okres:**
  - `today` = od lokalnej północy;
  - `week` / `month` = od lokalnej północy 6 / 29 dni temu;
  - `all` = wszystko.
  - Godzina UTC `h` należy do dnia lokalnego `(h·HOUR_MS + tz(h·HOUR_MS)).div_euclid(DAY)`.
- **Zmiana wobec poprzedniego okresu:** okres tej samej długości tuż przed bieżącym. `None` dla `all` i gdy poprzedni ma 0 tokenów.
- **Podium:** projekty z sumą miary > 0. Agent to ten z największym `active_ms` w projekcie.
- **Cache:** `cache_pct = cache_read / (input + cache_read + cache_write)`, `None` przy mianowniku 0.
- **Sesje:** `sessions` / `subagents` = pliki z `meta.started` w okresie (`sub` rozdziela).
- **`longest_ms`:** największe `active_ms` pliku z `sub == false` w okresie.
- **Wyścig:**
  - `agents`: trzy tory w stałej kolejności Claude, Codex, Router, tylko te z wartością > 0;
  - `projects`: top 5 według miary.
- **Kalendarz:** 182 dni kończące się dziś. Poziom 1–4 według kwartyli `active_ms` dni aktywnych w tym zakresie, 0 dla dni bez pracy.
- **Odznaki:**
  - Glutton: projekt z największymi tokenami, gdy > 0;
  - CacheMaster: projekt z najwyższym % przy tokenach ≥ 1 000 000;
  - NightOwl: `active_ms` w godzinach lokalnych 23–4 ≥ 30 min;
  - Marathon: plik główny z największym `active_ms`, gdy > 0.
- **Rekord:** dzisiejsze `active_ms` ≥ 1 h i większe niż każdego wcześniejszego dnia; `false`, gdy nie ma wcześniejszych dni.
