# UI polish (0.15) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the look of the panel and the Settings window (Claude-app style, with a theme option), then review the NSIS installer and replace the app icon.

**Architecture:** Panel logic (counts, warning dot, subagent collapse) goes into `panel/model.ts` as pure, tested functions; `App.tsx` and `panel.html` only render. Settings gets one token set in `settings.html` and a small component kit in `app/src/settings/ui/`; every tab is rewritten on top of it, with no per-tab CSS for controls. Theme is a new `theme` field in core `Settings`, applied as `data-theme` on `<html>` by one helper that every window calls.

**Tech Stack:** Rust (pets-core, Tauri crate `app/src-tauri`), React 19 + TS, Vite multi-page, vitest, pnpm; NSIS; `codex_generate_image` for the icon.

**Spec:** `docs/superpowers/specs/2026-10-02-ui-polish-design.md`

## Global Constraints

- Work on branch `feat/panel-redesign`; one commit per task; no version bump or release until the owner says so.
- All user-visible strings go through `app/src/i18n/{en,pl}.ts` (both languages, `i18n.test.ts` must stay green); no new hard-coded text.
- Colours only as tokens on `:root` in the page CSS, with `prefers-color-scheme` guarded by `:root:not([data-theme="light"])` plus `:root[data-theme="dark"]`. Light window `#FAF9F5`, dark window `#1F1F1E`, hairline `rgba(255,255,255,.07)` in dark, accent `#D97757` only for links, switch-on, focus.
- Keep the preview stage and the style cards with live previews; they are the only boxed elements on the Look tab.
- Controls with a fixed choice set use `Segmented`, `OptionCards` or `Select`, never a row of plain buttons.
- Settings content: one scrolling column, max width 680 px, no serif title, no cards except the two above and the Taskbar position option cards.
- Panel header icons are 28×28 frameless; the "N sessions" label is gone (`t().sessions(n)` no longer used in the panel).
- Commands: `pnpm -C app typecheck`, `pnpm -C app test`, `cargo test -p pets-core --lib`, `cargo test -p agent-pets` (from repo root).
- Visual checks in the browser pane (`pnpm -C app dev`, `/panel.html`, `/settings.html`) in light and dark, at the real window widths; use `get_page_text`/`read_page` for content, screenshots only at `scale: 0.5` for look.

## Review Focus

- Theme value missing or unknown in an old `settings.json` → falls back to `system` (core `or_default`), never breaks load.
- Stepper: empty field, `0`, `99`, `NaN`, pasted text → clamps to 1–8 on blur/commit, never saves an invalid value.
- Panel with 0 sessions, with only inactive sessions, with 12 subagents under one parent, with a stale/no-data Limits reading → each renders a sane state (empty state, "Clear inactive" only when needed, "+N subagents", one grey "No data" line).
- Card click must not fire when the `⋯` menu or a nested control is clicked; Enter/Space on the card opens, Esc closes the menu.
- Apps tab with a not-detected agent (dimmed, switch still reachable if it was enabled), and with an unknown future `AppId` (must not crash grouping).
- Dark/light switch while Settings and Panel are both open updates both without reload; `system` follows the OS.
- Installer: update over an older version keeps integrations; uninstall while the app runs; Polish and English strings both present.
