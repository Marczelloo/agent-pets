# 0.12: sprawdzenia (Cursor, Grok Build, ZCode)

## Automatyczne

Bramka: `cargo test --workspace` i `pnpm --dir app test --testTimeout=30000`, obie zielone na gałęzi `v0.12`.

| Obszar | Czym sprawdzone |
|---|---|
| Stare dane | `settings.json` z 0.11 bez `cursor`/`grok`/`zcode` (wszystkie wyłączone); wygląd i nadpisania nowych agentów po zapisie |
| Trasy | `/v1/events/{cursor,grok,zcode}` otwierają się i zamykają z przełącznikiem; zdarzenie przy wyłączonej integracji nie tworzy zwierzaka; zdarzenia należą do swoich agentów |
| `hook.exe --agent/--event` | Cursor: koperta z nazwą zdarzenia, zawsze odpowiedź pozwalająca iść dalej (`{"continue":true}` przy `beforeSubmitPrompt`, `{}` przy reszcie), także bez widżetu i przy złym wejściu; Grok i ZCode: koperta, brak wyjścia; id sesji Groka z `GROK_SESSION_ID`; zła nazwa zdarzenia → nic nie wysłane; ogromny prompt Cursora nie wychodzi z hooka |
| Obcy wywołujący | `caller`: Grok po `GROK_HOOK_EVENT` (także z JSON-em Cursora), Cursor po `cursor_version`, ZCode po `ZCODE_SESSION_ID` z `hookEventName`; hook Claude'a wywołany przez innego agenta nic nie wysyła; Claude uruchomiony z terminala ZCode dalej jest Claude'em |
| Cursor | każde zdarzenie z fixture'a, agent/proces/folder/model, id z `conversation_id` albo `session_id` i `safe_id`, tura przerwana, przerwana przez `aborted` i z błędem, podagent jako dziecko rozmowy, mapa narzędzi i teksty akcji, test prywatności (prompt, e-mail, załączniki, treść pliku) |
| Grok Build | każde zdarzenie z fixture'a, oba zapisy pól, tylko powiadomienia czekające na człowieka dają „czeka na Ciebie”, złe id i nieznane zdarzenie → nic, test prywatności (prompt, odpowiedź, wynik narzędzia), id sesji ze środowiska |
| ZCode | każde zdarzenie z fixture'a, `PermissionRequest` pyta o akcję i nigdy nie pokazuje `reason`, oba zapisy pól, złe id i nieznane zdarzenie → nic, test prywatności (prompt, wynik narzędzia) |
| Integracje | wykrycie po folderach; Cursor: jeden wpis na zdarzenie przy powtórnym włączeniu, dopisanie obok cudzych hooków z kopią, nietypowy plik nietknięty, bez `~/.cursor` odmowa, plik utworzony przez nas znika po wyłączeniu; Grok: zapis i usunięcie własnego pliku, cudzy `agent-pets.json` nietknięty; ZCode: dopisanie do konfiguracji bez ruszania reszty, zły JSON nietknięty, tworzenie `cli/`, pusty klucz `hooks` znika, ścieżka z `ZCODE_DATA_BASE_DIR`; odinstalowanie usuwa hooki wszystkich trzech |
| UI | przełączniki Cursor, Grok Build i ZCode z opisem i plakietką „eksperymentalne”, dopiski o braku „czeka na Ciebie” (Cursor) i stanu błędu (ZCode); kreator nie włącza eksperymentalnych agentów sam; `appFor` dla trzech |
| Wygląd | Cursor (czarny sześciokąt z jaśniejszą fasetką i jasną krawędzią), Grok (mały biały humanoid z czarnym wizorem, białymi oczami, logo Groka na klatce i czarnymi dłońmi) i ZCode (panda z uszami, łatami i niebieską opaską z „Z”) w każdym stylu, ruchu i scenie bez NaN; Pixel i Sticker rysują je jak Clean; oczy nad biurkiem; akcenty; wszystkie trzy w podglądzie zakładki Wygląd |

## Na żywo (z użytkownikiem)

- [ ] Wygląd Cursora, Groka i ZCode zaakceptowany na podglądzie (`looks-dev?cast=012`).
- [ ] Cursor (plan Hobby): działająca ścieżka `hooks.json`, powłoka komendy, stany, nazwy narzędzi, podpis „· Cursor”, skok do okna, `{}` nie zmienia pytań o zgodę, brak ducha Claude'a z włączoną integracją Claude Code.
- [ ] Grok Build: plik w `~/.grok/hooks` działa, `GROK_HOOK_EVENT`, brak ducha Claude'a i Cursora, nazwy narzędzi i `Notification`.
- [ ] ZCode: `hookEventName`, `ZCODE_SESSION_ID`, aplikacja nie nadpisuje naszych wpisów, nazwa `.exe` aplikacji.
- [ ] Regresja: Claude Code, Codex i opencode jak w 0.11.
